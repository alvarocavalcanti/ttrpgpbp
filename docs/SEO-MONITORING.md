# SEO monitoring

A short monthly cadence for the public site. Everything here uses free tools:
Google Search Console and Bing Webmaster Tools. No paid SEO service is needed.

## Where the SEO lives

| Concern | Source of truth |
| --- | --- |
| Public route paths, titles, descriptions, sitemap priority | `src/lib/publicRoutes.ts` (`PUBLIC_ROUTES`) |
| Per-route JSON-LD (`HowTo`, `Article`, `FAQPage`, breadcrumbs, `WebApplication`) | `src/lib/structuredData.ts` |
| Prerender, sitemap, robots | `scripts/seo/prerender.mjs` |
| Post-build checks | `npm run seo:verify`, `npm run seo:verify-hydration` |
| Social share card | `public/og-image.png` (`npm run seo:og`) |

Never edit `dist/` by hand — it is regenerated by `npm run build:seo` on every
deploy.

## Monthly checklist

- [ ] **Search Console → Pages (coverage).** Confirm the public routes are
  indexed and there are no "Crawled — currently not indexed" surprises. Fix a
  route that is not indexed before writing new content.
- [ ] **Search Console → Performance.** Look at the top queries and pages over
  the last 28 days. Note queries with impressions but a low click-through rate —
  those are title/description candidates.
- [ ] **Iterate titles and descriptions from real impressions.** Edit the
  matching entry in `PUBLIC_ROUTES` (the title must stay free of a raw `&`),
  then run `npm run build:seo && npm run seo:verify`. Ship through the normal
  PR flow.
- [ ] **Check rich results.** Run a changed guide through the Google Rich
  Results test and the Schema.org validator; `npm run seo:verify` already
  asserts the expected `@type` per route.
- [ ] **Bing Webmaster Tools.** Review coverage and top queries; Bing can
  import the Google Search Console property (see `DEPLOYMENT.md`).
- [ ] **Sitemap.** Confirm `https://rolebypost.com/sitemap.xml` returns 200 and
  lists the current routes. It is rebuilt on every deploy.
- [ ] **Record what changed.** Note any title/description edits in the PR that
  makes them so the next review can compare against the previous month.

## When a route is missing from the index

1. Check it is listed in `PUBLIC_ROUTES` and appears in `dist/sitemap.xml`.
2. Confirm it is not caught by an app-shell rewrite in `public/_redirects` or a
   `robots.txt` disallow (see `robotsDisallowPaths` in `src/lib/publicRoutes.ts`).
3. Re-run `npm run build:seo && npm run seo:verify` and inspect the generated
   HTML for a single `<h1>`, a canonical link, and the expected JSON-LD.
